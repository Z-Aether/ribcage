# Verifying in a browser

How an agent checks a page by driving the seeded local instance with Playwright over MCP (#25). The walk shows what is in the DOM, what the console reports and how the layout holds at desktop width and at 390 px. It is blind to the proxy: with DEBUG on, the app takes requests as plain HTTP, so CSRF and HSTS failures show only on the real deployment (#16, #25, #54).

## Before you start

- **The tools are `mcp__playwright__*`.** When they are deferred, load them with ToolSearch `+playwright browser`. The server is registered in the dev's private local scope, outside the repo. When the tools are missing, stop and report it: Claude in Chrome and other browsers are kept for debugging the real deployment (#25).
- **Install and `.env`** as `CLAUDE.md`'s *Running it* says, with `DEBUG=true`, the value `.env.example` carries. The seed refuses to run without it.

## Steps

1. **Seed and start.** Run `.venv/Scripts/python manage.py seededserver` (`.venv/bin/python` off Windows) as a background command. It rebuilds the database at `DATABASE_PATH` from nothing, the dev's local data included. It then prints the seeded voters and their password, and serves `http://127.0.0.1:8000/` without autoreload. The server's banner is buffered when its output goes to a file, so poll `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8000/login/` instead of waiting for the banner. Done when the poll answers `200`. After a code change, stop it as step 5 says and run it again; the restart reseeds. `--phase` picks the phase to seed, one of the five (#25, #74); `/` then shows that phase's page.
2. **Drive.** Navigate to `http://127.0.0.1:8000/…`: every cookie is `Secure`, so only a loopback address keeps them (#31). Assert on `browser_snapshot`, the accessibility tree, and act with its refs. Voter pages are behind the login wall, so log in at `/login/` as any seeded voter: the names are `SEEDED_DISPLAY_NAMES` and the password `SEEDED_PASSWORD` in `ribcage/seeding/management/commands/seed.py`. Admin pages, under `/console/`, are behind the admin login at `/console/login/`, with `ADMIN_PASSWORD` from `.env`; one context holds both sessions at once (#76). The MCP holds one browser context, so a check needing two voters signed in at once needs a plain Playwright script (#25).
3. **Check every page at both widths.** Take each page at the default 1280×720, then `browser_resize` to 390×844, then resize back before the next page. At each width, snapshot, then `browser_take_screenshot` with the filename `tmp/<ticket>-<page>-desktop.png` or `tmp/<ticket>-<page>-390.png`. A relative filename is taken from the repo root, so a bare one lands untracked beside `CLAUDE.md`; confirm the path the tool reports starts with `tmp`. Read each screenshot for overflow, overlap and illegible text. Screenshots are evidence for this check alone, never baselines and never committed (#25). Done when every page in scope has both screenshots and you have read each one.
4. **Read the console.** After the walk, call `browser_console_messages` with level `error` and `all` set, and expect it empty. Read the server's log for tracebacks too.
5. **Stop the server, and leave the browser open.** The browser is in-memory (`--isolated`) and goes with the session; `browser_close` hangs, so leave it uncalled. Stop the server by killing its process tree, sending the kill as a Bash call of its own, never batched with other calls:
   - **On Windows,** the venv's `python.exe` is a launcher, and its child interpreter keeps serving after the background task is stopped. Find the launcher's PID with `powershell -NoProfile -c 'Get-CimInstance Win32_Process | Where-Object { $_.ExecutablePath -like "*\.venv\*" -and $_.CommandLine -like "*seededserver*" } | ForEach-Object ProcessId'`, then run `taskkill //F //T //PID <pid>`. If the lookup prints nothing, find the PID by port with `powershell -NoProfile -Command "Get-NetTCPConnection -LocalPort 8000 -State Listen | ForEach-Object OwningProcess"` and kill that. Never stop the background task yourself (TaskStop): it leaves the child interpreter serving. Once the kill lands, the background task reports failed with exit code 1, which is expected.
   - **Off Windows,** the server is one process without autoreload: `pkill -f 'manage.py seededserver'`.

   Done when the step 1 poll no longer answers `200`.
6. **Report** each page at each width: what you did, what the snapshot showed, the console errors, and the screenshot filenames.
